🌿 Selva Booking — Estructura de carpetas

Mapa visual del proyecto Android. Cada carpeta tiene un propósito claro dentro de la arquitectura MVVM + Firebase.

Kotlin Jetpack Compose MVVM Firebase Madre de Dios

¿Cómo se organiza el código?

La app separa lo que se ve, la lógica, el acceso a datos y las reglas del negocio. Así cada parte es fácil de encontrar y modificar sin romper el resto.

UI (Compose) → ViewModel → Repository → Firebase / Local

📁 Raíz del proyecto

🏠
SelvaBooking/ Proyecto completo
▶
Concepto: Contenedor de todo — código, configuración Gradle, documentación y herramientas. Es lo que clonas del repositorio.
📱
app/ Módulo de la aplicación
▶
Concepto: El corazón del proyecto. Aquí vive todo el código Kotlin, recursos visuales, manifest y configuración Firebase. Al compilar, genera el APK.
  • build.gradle.kts — Librerías: Compose, Firebase, Navigation, Coil
  • google-services.json — Credenciales del proyecto Firebase
  • src/main/ — Código y recursos que van al APK
  • build/outputs/apk/ — APK generado (no se edita a mano)
📚
docs/ Documentación
▶
Concepto: Material de referencia para entender y presentar el proyecto — arquitectura, casos de uso y diagramas UML.
  • exposicion/ — Guiones por bloques (arquitectura, auth, cliente, admin)
  • diagramas/ — UML y casos de uso (.md y .puml)
  • estructura-carpetas.html — Este archivo
⚙️
gradle/ · gradlew · *.gradle.kts Sistema de compilación
▶
Concepto: Configura cómo se construye la app. Gradle descarga dependencias, compila Kotlin y empaqueta el APK. No contiene lógica de negocio.
🎨
figma-export/ · tools/ Diseño y scripts
▶
Concepto: Recursos auxiliares. SVGs de pantallas exportados desde Figma y scripts Python para generar assets de diseño.

🧩 Código fuente — app/src/main/java/com/company/selvabooking/

🚀
MainActivity.kt · SelvaBookingApplication.kt Arranque de la app
▶
Concepto: Punto de entrada. MainActivity muestra la primera pantalla y aplica el tema. Application crea los repositorios una sola vez para toda la app (como un "contenedor global").
📦
domain/model/ Entidades del negocio
▶
Concepto: Define qué cosas existen en Selva Booking: usuarios, hoteles, habitaciones, reservas. Son clases puras de datos, sin UI ni Firebase. Representan el "lenguaje" del dominio.
  • User.kt · UserRole.kt — Cliente, admin, gerente
  • Hotel.kt · Room.kt — Alojamiento y habitaciones con stock
  • Reservation.kt · ReservationStatus.kt — Reservas y estados (confirmada, terminada…)
  • Resena.kt — Opiniones de clientes
  • SavedPaymentCard.kt — Tarjeta guardada localmente
☁️
data/ Conexión con servicios externos
▶
Concepto: Capa más baja de datos. Habla directamente con Firebase y contiene datos de ejemplo. No decide reglas de negocio complejas — solo lee y escribe.
  • firebase/FirebaseAuthService.kt — Login, registro, sesión
  • firebase/FirestoreService.kt — Base de datos en tiempo real
  • firebase/StorageService.kt — Imágenes en la nube
  • SampleData.kt — Datos iniciales de prueba
🔄
repository/ Puente entre lógica y datos
▶
Concepto: El "intermediario inteligente". Los ViewModels no llaman a Firebase directamente — pasan por aquí. Aquí viven las reglas: bajar stock al confirmar reserva, expirar reservas terminadas, eliminar hotel con sus habitaciones, etc.
  • AuthRepository.kt — Usuarios, sesión, gerentes, admins
  • HotelRepository.kt — CRUD de hoteles
  • RoomRepository.kt — Habitaciones y control de stock
  • ReservationRepository.kt — Reservas y cambios de estado
  • ResenaRepository.kt — Reseñas y calificaciones
  • SavedCardRepository.kt — Tarjetas en el teléfono (local)
🧠
viewmodel/ Cerebro de cada pantalla (MVVM)
▶
Concepto: Prepara todo lo que una pantalla necesita mostrar y reacciona a acciones del usuario (buscar, reservar, guardar hotel…). Expone un UiState que la UI observa. No dibuja nada — solo piensa.
  • AuthViewModel.kt — Login y sesión global
  • HomeViewModel · SearchViewModel · HotelDetailViewModel — Flujo cliente
  • BookingViewModel · PaymentViewModel · MyReservationsViewModel — Reserva y pago
  • Admin*ViewModel.kt — Panel admin y gerente
  • ProfileViewModel.kt — Perfil compartido
🗺️
navigation/ Rutas y flujo entre pantallas
▶
Concepto: El "GPS" de la app. Define nombres de rutas, conecta pantallas en un grafo y decide a dónde ir según el rol del usuario tras iniciar sesión.
  • Routes.kt — Constantes: admin_hotels, client_home…
  • NavGraph.kt — Mapa completo de pantallas + drawer
  • NavigationDestinations.kt — Destino inicial por rol

🖼️ Interfaz — ui/

🔐
ui/auth/ Acceso al sistema
▶
Concepto: Puerta de entrada. Login, registro, recuperar contraseña y completar perfil del gerente la primera vez.
🏨
ui/client/ Experiencia del turista
▶
Concepto: Todo lo que hace un cliente: explorar hoteles, buscar, ver detalle, reservar, pagar y consultar sus viajes.
  • HomeScreen.kt — Inicio con destacados
  • SearchScreen.kt — Búsqueda y filtros
  • HotelDetailScreen.kt — Detalle del hotel
  • BookingScreen.kt · PaymentScreen.kt — Reserva y pago
  • MyReservationsScreen.kt — Mis reservas
👔
ui/admin/ Panel administrador y gerente
▶
Concepto: Pantallas de gestión. El admin supervisa; el gerente opera su hotel. Varias pantallas se reutilizan en modo distinto según el rol.
  • AdminDashboardScreen.kt — Métricas e ingresos
  • AdminHotelsScreen.kt — Lista de hoteles
  • AdminRoomsScreen.kt — Habitaciones del hotel
  • AdminReservationsScreen.kt — Historial de reservas
  • AdminGerentesScreen.kt · AdminAdministradoresScreen.kt — Gestión de cuentas
🧩
ui/components/ Piezas reutilizables
▶
Concepto: "Lego" de la interfaz. Botones, campos de texto, tarjetas de hotel y filtros que se usan en muchas pantallas para mantener un diseño consistente.
🎨
ui/theme/ Identidad visual
▶
Concepto: Colores selva, tipografías y tema Material 3. Define cómo se ve toda la app de forma uniforme.
📋
ui/profile/ · splash/ · support/ · navigation/ Pantallas compartidas
▶
Concepto: Perfil de usuario, pantalla de carga inicial, ayuda y menú lateral — comunes a varios roles.

🔧 Utilidades y recursos

🛠️
utils/ Herramientas compartidas
▶
Concepto: Funciones auxiliares usadas en muchos lugares: formatear fechas y soles, validar emails, opciones de formularios de hotel, mensajes de error traducidos.
🖼️
res/ Recursos Android (no Compose)
▶
Concepto: Archivos que Android necesita fuera del código Kotlin: textos por defecto, icono de la app, temas XML base y reglas del sistema.
  • values/strings.xml — Cadenas de texto
  • drawable/ · mipmap/ — Iconos e imágenes
  • AndroidManifest.xml — Configuración de la app

👥 ¿Qué carpeta usa cada rol?

Cliente

Reserva hoteles en la selva.

  • ui/client/
  • viewmodel/Home*, Search*, Booking*…

Gerente de hotel

Gestiona su alojamiento y ve reservas.

  • ui/admin/ (modo gerente)
  • MANAGER_* rutas

Administrador

Supervisa la plataforma y cuentas.

  • ui/admin/ (modo consulta)
  • ADMIN_* rutas
